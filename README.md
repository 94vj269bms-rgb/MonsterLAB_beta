# MONSTER LAB — 広告導入準備版（PWA）

## 方針
- 通常のディスプレイ広告を優先
- 広告枠は「モンスター図鑑」タブ内だけ
- 配合ラボ・発見ログには広告を置かない
- スマホ幅でも横はみ出ししにくいレスポンシブ枠
- 現時点では実際の広告IDを持っていないため、広告はプレースホルダー表示です。収益化済みではありません。

## 公開手順（GitHub Pages）
1. GitHubで新しいリポジトリを作成（例: `monster-lab`）。
2. ZIPを解凍し、中のファイル一式（`index.html`、`manifest.webmanifest`、`sw.js`、アイコン類など）をリポジトリのルートにアップロード。
3. リポジトリの **Settings → Pages** を開く。
4. **Deploy from a branch** を選び、Branch=`main`、Folder=`/(root)` にして保存。
5. 公開URL（通常 `https://ユーザー名.github.io/リポジトリ名/`）にアクセスし、iPhone Safariで動作確認。
6. iPhoneではSafariの共有メニュー → **ホーム画面に追加**。初回ロード後、オフライン起動も確認。

## AdSense導入の順序
1. 公開URLを用意し、スマホ・PCで正常にアクセスできることを確認。
2. AdSenseに申し込み、サイトを追加する。サイト審査が通るまでは広告配信・収益は始まりません。
3. 審査前に、サイトの内容を充実させる。ゲームだけの単一画面は「有用なコンテンツが少ない」と判断される可能性があります。ゲームの遊び方、配合ルール、レア度・確率の説明、データ保存・リセット方法、運営者情報、問い合わせ先、プライバシーポリシーなどを、実際に運営できる内容で追加してください。審査通過を保証するものではありません。
4. AdSenseアカウントで「広告 → 広告ユニット」からディスプレイ広告ユニットを作成し、発行されたコードを取得する。
5. `index.html` の `<head>` に、AdSense管理画面で発行されたサイト接続用コードを追加する。
6. 図鑑の `id="encyclopediaAdSlot"` 内に、広告ユニットコードを追加する。**Publisher IDやad-slot IDを推測・捏造しないこと**。Googleが発行した値をそのまま使う。
7. AdSenseの「サイト」画面で審査状況を確認。承認後に広告が表示される。審査には数日、場合によっては2〜4週間程度かかることがあります。
8. AdSenseから`ads.txt`を求められたら、発行された内容をサイトのルートに配置し、`https://公開URL/ads.txt`で表示されるか確認する。GitHub PagesのサブパスURLではルート配置に制約があるため、ads.txtや独自ドメインを使う段階でホスティング構成を再検討すること。

## 実際のAdSenseコードの配置
- サイト接続用コードはGoogleのAdSense管理画面からコピーし、`<head>` 内に貼る。
- ディスプレイ広告ユニットのコードは、図鑑の `encyclopediaAdSlot` 内に貼る。
- 現在の図鑑はタブ切替式の単一ページです。AdSenseのコードを動的に何度も挿入したり、広告を複製したりしないでください。初回の図鑑表示時に一度だけ広告ユニットが初期化される実装にする必要があるため、広告コードを追加する際はGoogleの最新コードと動作仕様を確認してから実装してください。
- 広告を「広告」と明確に表示し、広告クリックを促す文言を置かないでください。自分で広告をクリックしたり、他人にクリックを依頼したりしないでください。
- 自動広告は配置場所をGoogle側が選ぶため、「図鑑だけ」という方針とは相性がよくありません。まずは手動のディスプレイ広告ユニットを推奨します。

## スマホ/PWAに関する注意
- PWAとしてホーム画面に追加しても、広告配信にはインターネット接続が必要です。
- オフライン時はゲーム本体が動いても広告は表示されない場合があります。
- セーブデータは端末・ブラウザ内のlocalStorageです。別端末への自動同期はありません。
- GitHub Pagesは静的ホスティングです。ゲームの配布には使えますが、独自ドメインやルートの`ads.txt`要件を満たしたい場合は制約を確認してください。
